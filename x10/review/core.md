# Ядро NGINX: рабочие заметки чтения

Зафиксирован commit `148c75678cd4171338c31d4ed4c02411736d5fe9`, версия из заголовка 1.31.9. Покрытие чтения записывается отдельно; этот документ не означает полный аудит безопасности.

- ngx_core.h: типы callback/объектов и раздельные return states OK/ERROR/AGAIN/BUSY/DONE/DECLINED/ABORT; функции вызывающего слоя должны учитывать конкретный контракт, нельзя заменить общим boolean.
- ngx_module.c/h: static modules и dynamic modules имеют version/signature gate. Индексы и ctx_index должны оставаться свободными также в old_cycle; порядок модулей влияет на инициализацию/filter chain. Совместимость бинарных модулей — отдельный критерий fork, одной совместимости nginx.conf недостаточно.
- ngx_palloc.c/h: small allocations из aligned linked pool blocks; крупные alloc отдельно tracked; cleanup callbacks выполняются перед освобождением. pfree освобождает только крупные allocation; reset не является заменой destroy с cleanup. Нельзя добавлять malloc/free для каждого сетевого буфера без измерения и понимания lifetime.
- ngx_array: pool-backed growth может расширить последнюю allocation in place, иначе копирует с удвоением capacity. ngx_list: неподвижные parts для стабильных адресов. ngx_queue: intrusive queue и stable merge sort. Эти структуры несут контракты ownership и стабильности адресов.
- LICENSE прочитана: сохранять copyright/условия/disclaimer при распространении исходников и бинарников. Лицензионные notices остаются в native базе.

Непроверенное: данный проход не доказывает отсутствие дефектов, производительность или переносимость; исходник ещё не собран и не запущен в этом этапе.

- nginx.c целиком: main init ordering (OS/cacheline before CRC/slab, socket inheritance, modules→ngx_init_cycle), -t/-T validation беззапуска worker, master/single selection, binary upgrade через inherited listening FDs и pid rename with failure rollback; env allowlist с TZ и cycle cleanup; load_module до modules_used и lifetime dlclose. Нативный graceful handover уже существует, его нужно сохранить.
- ngx_buf.c/h: memory/file flags, pos/last и file_pos/file_last обновляются согласованно; chain копирует ссылки на buf, а не payload; free/busy перерабатывается только при совпадении tag и полном потреблении. special flush/sync/last_buf тоже семантический сигнал. coalesce_file ограничивает последовательные участки одного FD и учитывает page alignment.

- ngx_conf_file.c/h целиком: общий tokenizer с quotes/escapes/comments и лимитом4KiB parameter, contexts/arity/module type проверяются до setter; include/glob и conf_prefix/prefix различаются; dump содержит полные конфиги и потенциальные secrets. X10 dry-run должен вызывать родной nginx -t, а не подменять grammar собственным JSON. Инструменты -T/control dump не показывать неавторизованным пользователям.
- ngx_output_chain целиком: fast path не копирует пригодный singlebuf; копирование зависит от need_in_memory/need_in_temp/sendfile/directio/align; AIO и threads возвращают AGAIN с retained state. Рециклинг не происходит до output_filter и проверки busy/tag. chain_writer учитывает c.buffered и продолжает запись через posted_next, а не считает syscall окончанием ответа.
- ngx_thread_pool.c/h целиком: bounded taskqueue, task.event.active защищает повторную постановку; worker threads блокируют сигналы, task handlers выполняются вне event loop, completion переносится через locked done queue + ngx_notify в loop. task memory/context должны дожить до completion; shutdown выполняется специальными задачами. Увеличение потока не автоматически ускоряет неблокирующий HTTP.

- ngx_hash.c/h целиком: exact lookup предшествует head/tail wildcard, low pointer bits кодируют wildcard node/data и включение базового hostname. Bucket layout выравнивается по cacheline/pointer, итоговый hash строится на конфигурации и становится read-only lookup. X10 validation должен сохранять приоритеты exact/.domain/*.domain/domain.* и диагностику дубликатов.
- ngx_parse.c/h и ngx_parse_time.c/h: overflow guard до умножения и суммирования; units и допустимый порядок имеют native semantics. Month/year в конфигурационной длительности — фиксированные30/365дней, не календарная операция. HTTPdate parser поддерживает три исторических формата; hardening требует совместимых дифференциальных тестов, а не переписывания через стандартную Date.
- ngx_times.c/h целиком: 64 cached slots и lock-free reads, update с trylock+barrier; сигнальный путь не вызывает небезопасный localtime. Event timers используют monotonic time при наличии, календарные строки — wall clock. Нельзя заменить все часы одним Date.now без разграничения.
- ngx_log.c/h и ngx_syslog.c/h целиком: bounded2048byteerrorbuffer, severity chain, diskfull suppression на секунду, optionaldebug memoryring; syslog UDP nonblocking и busy recursion guard. Это не durable journal с подтверждением доставки. Добавлять аудит лучше отдельным bounded opt-in control-plane каналом, без блокировки hot path.
- ngx_proxy_protocol.c/h целиком: native v1/v2 parser/writer, separate transport/family handling, pooledaddress/TLVmemory; IPv4mapped promotion/demotion; TLS authority/ALPN/cert metadata и CRC32c в writer. Входной v2 reader обрабатывает STREAM, unsupportedLOCAL/transport пропускает до declaredend. CRC TLV при чтении не превращает метаданные в доверенную identity: trust network/config boundary остаётся обязательным.
- Прочитаны README, CONTRIBUTING, SECURITY, SUPPORT, CODE_OF_CONDUCT. Source tests находятся в отдельном официальном nginx-tests repo; весь ecosystem и сторонние/коммерческие модули не входят в эту копию исходников. Внешние сообщения или CLA не отправлялись/не принимались.

Часть core распределена другим читателям: resolver/inet/string/regex — core-support; file/cache/structures/crypto/JSON — core-structures; connection/cycle — core-lifecycle. Их фактические диапазоны не приписываются личному чтению root. Командная сводка объединяет отдельные ledger по path и SHA256.
