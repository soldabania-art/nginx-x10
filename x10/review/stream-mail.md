# NGINX stream и mail: чтение исходников

Commit `148c75678cd4171338c31d4ed4c02411736d5fe9`, версия в исходниках `1.31.9`. Рабочий аудит исходников, без сборки и runtime-испытаний. Фактические диапазоны чтения и статусы каждого файла: `stream-mail-coverage.json`. Полнота не предполагается до завершения ledger.

## Рабочие заметки по прочитанному

- `src/mail/ngx_mail.c` прочитан полностью: `mail{}` выделяет контексты модулей, вызывает create/init/merge callbacks, группирует listeners по семейству/порту. Explicit bind идёт раньше wildcard; wildcard позволяет общий socket и выбор по локальному адресу. Настройки SSL и PROXY protocol переносятся в address-specific runtime configuration. Сохранить merge/order semantics, IPv4/IPv6, socket keepalive и backlog; упрощение до одного listener теряет поведение.
- `src/mail/ngx_mail.h` прочитан полностью: отдельные POP3/IMAP/SMTP auth-state enums и parser state; сессия хранит login/passwd, IMAP tag/literal state, SMTP HELO/from/to, resolver/proxy, STARTTLS/auth flags. Mail — протокольный front end до аутентификации, а не HTTP reverse proxy. Пароли и команды требуют redaction в будущей наблюдаемости.

- Mail auth HTTP (`ngx_mail_auth_http_module.c`): отдельный connection и pool, раздельные read/write timers, инкрементальный разбор status line/headers. Контракт определяется `Auth-Status` (OK/WAIT/ошибка), `Auth-Server`/`Auth-Port`, опциональной подменой user/pass, задержкой Auth-Wait и SMTP Auth-Error-Code. Адрес назначения разбирается как IP, порт 1–65535; это не произвольный HTTP redirect. Auth backend в этом модуле использует plain HTTP/1.0 или Unix socket, не TLS; credentials escape передаются в заголовках. Возможные улучшения — защищённый transport/observability/redaction с сохранением протокола и явным latency budget, без необоснованного кэширования auth.
- Mail core (`ngx_mail_core_module.c`): протокол определяется явно или портом; defaults timeout60s, resolver_timeout30s, max_errors5. Сохранить listener options bind/backlog/buffers/IPv6/MPTCP/SSL/keepalive/PROXY и ошибки duplicate address.
- Mail handler: PROXY читается перед TLS и применяется realip handler; STARTTLS возвращает управление protocol init после handshake, verify_client влияет на протокольную ошибку и session cache. `ngx_mail_send` сохраняет partial writes/blocked flag; command buffer/max_errors ограничивают pre-auth parser, auth_wait живёт на timer без busy loop. IMAP сохраняет tag, literal/continuation state; STARTTLS очищает буфер команд. Новая панель должна показывать причины отказа по фазам, не раскрывая passwd/login в публичных метриках.

### Mail: полное чтение 19 файлов завершено

- `ngx_mail_parse.c`: incremental parsers различают NGX_AGAIN/OK/invalid; сохраняют состояние на границе TCP-фрагментов. IMAP tag ограничен, quoted/backslash arguments и синхронные/несинхронные literals требуют отдельного состояния; literal length проверяется на overflow. Ошибочная строка пропускается до LF, подозрительный non-sync literal может завершить сессию. Нельзя заменить всё split по CRLF. Нужны corpus/fuzz и fragmentation tests, а не заявление о найденной уязвимости.
- POP3 поддерживает USER/PASS, APOP и AUTH exchanges; буфер pre-auth128B, capability merge включает LOGIN при plain. IMAP client buffer по умолчанию page-size; capability STARTTLS-only скрывает AUTH и добавляет LOGINDISABLED. Сохранить capability/auth-policy correspondence, salts и protocol-specific replies.
- SMTP handler делает PTR, проверяет допустимый hostname, затем forward resolution и совпадение IP; сбой различает UNAVAILABLE/TEMPUNAVAIL. greeting_delay отвергает команды до greeting как improper pipelining. HELO/EHLO, AUTH, MAIL/RCPT auth-none, RSET и STARTTLS имеют отдельные переходы; STARTTLS сбрасывает сведения pre-TLS по RFC3207. Авторизация auth-none вызывается после первого RCPT. Сохранить порядок; панель может явно объяснять DNS/auth/greeting-delay latency.
- Mail proxy выполняет аутентификацию к назначенному auth backend серверу: POP3 USER/PASS; IMAP LOGIN с literals/continuations и tagged reply; SMTP HELO/EHLO→XCLIENT/optional AUTH PLAIN/MAIL/RCPT. Затем обычный двухсторонний byte tunnel с двумя буферами, partial write/backpressure, EOF drain и proxy_timeout (default24h). Частичная отправка небольших upstream login-команд считается fatal; перспективное изменение требует воспроизведения EAGAIN/partial-write и строгой protocol regression. Не вводить replay после произвольных байтов.
- Mail PROXY output поддерживает off/on(v1)/v2; header отправляется целиком до чтения greeting, NGX_AGAIN планируется через write event. Realip принимает PROXY source только от set_real_ip_from trusted peer; клиентский адрес нельзя безусловно брать из внешнего header. Сохранить trust boundary и IPv6/Unix cases.
- Mail SSL: starttls off/on/only; implicit TLS через listen ssl; ALPN привязан к выбранному mail protocol. Certificate/key arrays должны соответствовать, TLS policy/verify modes/trusted chain/CRL/session tickets/cache/password file/conf_commands сохраняются. Общая SSL-реализация находится вне этого набора файлов и здесь не объявляется прочитанной. Улучшать управление сроками/ротацией сертификатов и диагностику handshake, измеряя failure rate/latency, без утверждения, что TLS отсутствует.

### Stream core, listener и допуск

- `ngx_stream.c/.h`: компиляция фаз POST_ACCEPT→PREACCESS→ACCESS→SSL→PREREAD→CONTENT и отдельная LOG; handlers внутри фазы идут в reverse registration order. Per-server config merge, exact/wildcard/regex virtual names и listener default_server уже существуют. Сохранить модульный ABI и порядок фаз: перенос allow/realip/preread меняет смысл конфигурации.
- `ngx_stream_core_module.c`: generic phase различает OK/DECLINED/AGAIN/DONE/error. Preread умеет MSG_PEEK на подходящих kqueue/epoll paths и чтение с сохранением буфера иначе; буфер/timeout ограничены (defaults16KiB/30s), proxy_protocol_timeout30s, tcp_nodelay on. Для UDP listen отклоняет несовместимые TCP/TLS/PROXY options; не генерировать универсальный блок для TCP и UDP. server_name exact/wildcards/PCRE и normalize/validate host сохраняются.
- `ngx_stream_handler.c`: сессия TCP/UDP получает config по local-address/default-server, отдельные counters/start-time/variables, PROXY parser до phase engine. Finalize записывает внутренний status (200/400/403/500/502/503) и LOG hooks, затем SSL/socket/pool cleanup. Эти status не означают, что произвольному TCP-клиенту отправлен HTTP status.
- Access first-match поддерживает IPv4, IPv4-mapped IPv6, IPv6 и Unix all; отсутствие совпадения — DECLINED. `limit_conn_zone` уже предоставляет выражение-ключ и shared memory accounting между workers; limit_conn/dry_run/log_level/status, cleanup на выходе/отказе, mutex+rbtree и slab limits — обязательные semantics. Пустой key пропускается, key>255B логируется/пропускается; внедрение персональных квот поверх ядра должно учитывать эту политику, а не объявлять лимиты отсутствующими.

### Stream routing, variables, logging и data chains

- `geo`: CIDR IPv4/IPv6 radix и отдельно IPv4 ranges с разбиением high16/low16, overlap/split/delete/default; повторяющиеся values интернируются. Большая единственная ranges include может создать binary cache; чтение сверяет magic/version/pointer size/endian/mtime/size/CRC32, затем восстанавливает pointers. Не переносить такой blob между архитектурами и не считать CRC аутентификацией данных. `volatile` управляет кешированием переменной.
- `geoip`: в данном commit уже есть как legacy GeoIP, так и MaxMindDB/MMDB backend (country/org/city), mmap/read typed fields, IPv4-mapped IPv6, alpha2→alpha3 и cleanup. Нельзя предлагать MMDB как отсутствующую возможность. Механизм обновления баз/их provenance, typed config validation и измерение повторных lookup — возможные работы control plane.
- `map`, `set`, `split_clients`, `variables`, `script`: lazy exact/hash/wildcard/regex/default; map hostnames/volatile/include; set выполняется в PREACCESS; split_clients использует стабильный MurmurHash2 и cumulative percent, не случайный выбор на каждый пакет. Variable engine сохраняет indexed/no-cacheable/weak/prefix semantics, recursion depth100, captures; complex values компилируются в отдельные length/value passes с bounds checks. Панели нужен dependency-aware lint и explain выбранной ветки, не замена native engine внешним LLM на data path.
- `pass` — внутренний TCP connection handoff существующему local listener, не proxy_pass: запрещает UDP и уже считанные preread bytes, cycle cap10; MSG_PEEK preread особенно важен для последующей передачи сокета. `return` выдаёт вычисленный текст через top filter и last_buf, с5s write timeout.
- Write filter хранит цепочки отдельно для направлений upstream/downstream, проверяет ненулевые/неотрицательные buffer sizes, flush/sync/last markers, вызывает send_chain, освобождает отправленные chain links, сохраняет remaining chains и NGX_AGAIN/lowlevel buffered. Это уже backpressure; новые filters обязаны соблюдать ownership/flags.
- Stream logging: `log_format` компилируется; escape default/json/none, `access_log if=`, off, variable filenames/open cache, shared per-file buffer+flush timer+optional gzip, syslog без buffering. Disk-full1s skip и повторное логирование ошибок не чаще примерно1min меняют наблюдаемость. Variable values повторно проверяются на фактическую длину при copy. Возможные улучшения — bounded/exported logging loss counters и operator schema, с измерением throughput/p99 при тех же log policies; не включать дорогой logging незаметно в comparative benchmark.

### TCP/UDP proxy и TLS

- `ngx_stream_proxy_module.c` прочитан целиком: static upstream/complex proxy_pass, runtime resolver, transparent/local bind и socket options; peer.init/get/free/notify, per-attempt timings/bytes и backup/failure paths. Defaults connect_timeout60s, idle proxy_timeout10min, buffer16KiB, next_upstream on с ограничиваемыми tries/time, half_close off. Не путать idle timer с общим deadline сессии.
- TCP путь сохраняет preread buffers, PROXY v1/v2 header, две стороны output/busy/free chains, download/upload byte-rate delays и partial sends. half_close on делает shutdown(write) после EOF/drain и ожидает EOF обеих сторон. UDP lifetime определяется proxy_requests/proxy_responses, пакетными counters, timeout и удалением UDP association; это не TCP stream с другим названием. Workers shutdown завершают UDP отдельно.
- Failover применяется на connect/handshake/setup failures с peer.free(NGX_PEER_FAILED), tries/time limit; buffered data запрещает next-upstream. Это не произвольный replay приложенческих запросов. Сохранить правила до оптимизации tail latency.
- Upstream TLS уже имеет SNI/verify-name, cert chain/CRL, client certificate/key через variables и bounded certificate cache, session reuse, dynamic ALPN и conf commands. Defaults proxy_ssl_verify off и proxy_ssl_server_name off: control plane может делать проверяемый безопасный профиль, явно показывая изменение policy, не объявляя отсутствующий TLS. PROXY header к TLS upstream отправляется до TLS handshake.
- Stream TLS termination (`ngx_stream_ssl_module.c/.h`) — отдельная SSL phase: SNI выбирает virtual server и переносит SSL_CTX, verify depth/options/log context; renegotiation rejection, ALPN, dynamic certificates/cache, client verify/CRL/OCSP/stapling, session tickets/shared cache. В этом commit уже есть ssl_ech_file и ECH status/outer-name variables, certificate compression. Поддержка зависит от общей SSL library/platform и здесь runtime не проверена.
- SSL preread читает ClientHello без расшифровки/терминации TLS, сохраняет состояния между records/fragments, валидирует lengths, извлекает SNI/ALPN/version и может сменить srv_conf через native virtual names. Это данные ClientHello, не подтверждённая identity. ECH inner SNI нельзя обещать увидеть пассивному preread; отдельно тестировать TLS1.3/ECH/large+fragmented ClientHello и fallback.
- `upstream.c/.h`: уже есть server weight/max_conns/max_fails/fail_timeout/backup/down, runtime resolve/service(SRV) при zone build; method flags ограничивают допустимые параметры. Variables connect/first-byte/session/bytes отражают все попытки через comma-separated values. Weighted least_conn делит connections по weight и RR при равенстве, исключает tried/down/failed/max_conns, умеет backup и защищает generation при shared updates.

### Балансировщики и shared zones: полное чтение завершено

- Smooth weighted round robin: effective/current weight, tried bitmap, max_conns, max_fails/fail_timeout, backup, post-connect recovery и special single-peer semantics. Общие peers имеют generation, refs и zombie lifetime; удалённый DNS peer живёт до отпускания последней ссылки. SSL sessions per-peer кэшируются и сериализуются для shared zone с ограничением максимального размера. Нельзя заменить список JavaScript-массивом без потери межпроцессной семантики.
- Hash: обычный hash совместим с Cache::Memcached formula; consistent hash строит160points на единицу веса, сортирует/удаляет совпадающие points и rebuild при смене generation. Невозможный выбор или20попыток переводит к RR. Порядок/алгоритм hashing — совместимость affinity, а не только скорость. Random использует weighted ranges+binary search; random two выбирает между двумя по weighted connection count, с теми же eligibility checks и bounded fallback.
- Native `least_time connect|first_byte|last_byte [inflight]` уже в этом snapshot: per-peer EMA0.05new/0.95old, ETA учитывает connections/weight и optional незавершённую работу,20ms clusters и cap5000ms, slow peers получают шанс через decay. Не включать failed attempts как быстрые успешные samples. Это существующая адаптация; нельзя обещать её как новую уникальную AI-balancing функцию.
- `zone` хранит peers в shared slab memory; config generation инвалидирует per-session выбор/таблицы. На reload preresolve копирует ранее разрешённые адреса в новый zone/config; worker timers обновляют DNS/SRV. Transient DNS errors сохраняют текущие peers и ставят retry; NXDOMAIN даёт пустой набор и удаление. SRV priority определяет primary/backup, weight может прийти из DNS; add/remove обновляют total_weight/tries/number/generation, с mutex/rwlock и refs/zombie cleanup. Shared zone не является распределённым кластером.

## Покрытие и предел вывода

Все **52/52 файла,36 605/36 605 строк** назначенного `src/mail`+`src/stream` прочитаны полностью; ledger: full_read52, partial0, structural0, unread0. Каждый chunk выведен без truncation; readRanges покрывают1..EOF, SHA-256 связывает запись с pinned source. Это статическое чтение, не proof безопасности, полноты protocol compliance, runtime эффективности или выигрыша10×. Общие core/event/OS/OpenSSL реализации и внешние библиотеки не включены в этот ledger; их аудит ведут другие назначения. Исходники NGINX и продукт не изменялись.
