# HTTP core and protocols: source reading ledger and findings

Source: NGINX 1.31.9, commit `148c75678cd4171338c31d4ed4c02411736d5fe9`. Assigned scope: 42 files, 44,678 lines. All assigned source text, including tables, has been read in full in bounded, untruncated outputs. The JSON ledger records file hashes and actual inclusive read ranges. No NGINX or product implementation is changed.

This is a source-reading and compatibility report. It is not a proof of protocol compliance, a completed security audit, a performance result, or evidence that a native fork is implemented. Native compilation and runtime protocol tests were not performed by this reader during this assignment. Upstream/cache modules, event backends, TLS internals and the QUIC transport are outside this manifest; other readers cover them separately.

## Read batch 1: request and module interfaces

Fully read `src/http/ngx_http_request.h` (1–635), `src/http/ngx_http.h` (1–203), `src/http/ngx_http_config.h` (1–75).

- A request is not a socket or one response callback. `ngx_http_request_t` keeps `main`, `parent`, posted/subrequest lists, cleanup chain, request pool, per-module contexts, parser state, body/filter flags, event handlers, count/subrequest/blocked counters, and asynchronous/AIO state. Fork changes must preserve this lifetime model rather than adding an independent global response counter.
- Request parsing and request-body parsing have persistent states: `r->state`, saved header/URI pointers, chunked `state/size/length`; buffers may be partial across event callbacks. Parser changes require split-at-every-byte tests.
- Framing is explicit: input stores both Content-Length header/numeric value and Transfer-Encoding/chunked state. Output has distinct header/trailer lists and content length. Preserving protocol behavior requires following the parser, framing validation, body filters and finalization together.
- Public interfaces distinguish body buffering, unbuffered body reading, body discard, header/early-hints/body filters, special responses, and request finalize/free/close. A new body-size or concurrency policy must interact with all relevant paths.
- HTTP module configuration has main/server/location arrays and create/init/merge callbacks. A compatible fork should extend the existing directive/configuration lifecycle; bypassing it would break module assumptions and inheritance.
- Limits visible in the interface include URI changes 10, subrequests 50 and blocked 250. Enforcement was subsequently traced in batches 4 and 5; reading declarations alone does not verify runtime behavior.

## Read batch 2: request implementation and body entry

Fully read `ngx_http_request.c` (1–4235); body reader read through line450.

- Accept initializes per-address default virtual-server configuration, read/header timer, reusable-connection state and separate event handlers. QUIC streams dispatch before TCP TLS/HTTP paths. Cleartext HTTP/2 preface detection and TLS ALPN feed the HTTP/2 engine; a generic HTTP/1-only listener cannot replace this without feature loss.
- TLS SNI selects configuration/certificates before request parsing. Later Host virtual-server selection can return421 when certificate verification is enabled and the requested name differs from negotiated SNI. Native fork tests must cover SNI/default/wildcard/regex names, certificate verification and Host differences together.
- `ngx_http_process_request_headers` changes server configuration when Host is seen, enforces `max_headers`, supports configured invalid-header/underscore policy, and handles incremental large-buffer relocation. URI414 and internal header494 are distinct paths. Keep exact baseline behavior rather than substituting the prototype's DNS-only host validator: this NGINX validator accepts permitted URI reg-name characters, bracket literals, numeric ports and normalizes case/trailing dot.
- Unique header processing rejects duplicates (including Content-Length, Transfer-Encoding, Expect, Authorization and Host). Final validation rejects TE onHTTP/1.0, CL+TE together, invalid CL; only exact case-insensitive chunked is accepted, other transfer codings produce501. HTTP/1.1 requires Host. TRACE is denied; CONNECT has an explicitHTTP/1.1 +allow_connect policy and rejects bodies. These must remain differential regression cases.
- `client_body_early_read` predicates may start body reading before normal phase processing, with declared-size checks, discard and proper count/finalize handling. A new request admission module cannot assume all bodies are read only in one content handler.
- Finalization distinguishes NGX_DONE, DECLINED, errors, special responses, subrequests, background requests, buffered output, post actions and protocol streams. `ngx_http_close_request` decrements main count, waits for count/blocked zero, then dispatches HTTP/2 stream close or frees request/connection. Cleanup callbacks are detached before invocation to prevent double processing; logging and pool release have explicit guards.
- A response finishing does not imply safe keepalive: reading_body disables keepalive and selects lingering close. Pipelined bytes are retained separately while other header buffers are freed. Idle keepalive frees buffers and can reconstruct them later. Lingering close half-closes writes then drains reads with per-read and overall deadlines. Fork limits/drain logic must preserve these ownership and wire behaviors.
- Body reader increments main count, routes HTTP/2/3 to protocol-specific readers, handles preread bytes, buffered/unbuffered modes, busy/free chains, body timeout and callback completion. Its remaining implementation was then read in batch 3.

Proposed native preservation tests from these files: fragmented request/header buffers and relocation; duplicate/framing ambiguity; request line authority versus Host; SNI/Host mismatches withmTLS; earlybody/Expect/bodylimit combinations; subrequest+postaction+buffered/AIO finalization; keepalive pipelining after discarded/unfinished bodies; timeout/clientabort logging and one-time cleanup; graceful exit with keepalive-minimum and lingering deadlines.

## Read batch 3: complete HTTP/1 body and parsers

Fully read `ngx_http_request_body.c` (1–1387) and `ngx_http_parse.c` (1–2485).

- Body ownership includes borrowed preread buffers, free/busy chains, downstream buffering, optional temporary files, and asynchronous discard. Unbuffered downstream backpressure removes the body timer while the consumer owns progress; buffered paths retain timeout handling. File-only bodies, including empty ones, and persistent/clean/group-access temporary-file flags are part of the behavior to preserve.
- Length and chunked filters stop exactly at the body boundary and preserve excess pipelined bytes. Chunked size checks use subtraction before accepting a new chunk; the save filter enforces a single final buffer. Body EOF, downstream buffer release and request lifetime completion are separate events.
- Discard has its own count increment, read callback, lingering deadlines and finalization; it parses chunk boundaries rather than draining arbitrary bytes from a keepalive connection. Expect is evaluated once, only for applicable HTTP/1.1 requests, and exact `100-continue` triggers the interim response.
- Request-line, header and URI parsers are resumable state machines. Compatibility includes unknown syntactically valid methods, absolute-form URIs, CONNECT authority form, optional leading CR/LF, baseline HTTP/0.9 GET behavior, and platform-specific backslash handling. Header name policy distinguishes invalid syntax from configurable ignored names; duplicate-header semantics are enforced separately by the request layer.
- URI normalization tracks literal query/fragment delimiters separately from percent-decoded characters, rejects NUL and traversal above the root, and optionally merges slashes. Unsafe internal URI parsing checks traversal before and after decoding. Do not replace this with a generic URL parser without differential evidence.
- The chunked parser requires CRLF for chunk framing and trailers, guards hexadecimal accumulation and estimated-length overflow, preserves partial parser state, and optionally stops before trailers for the caller. Its acceptance differs from the request/header parsers' tolerated bare LF, so one shared line parser would change behavior.
- Status-line parsing accepts the existing IIS dotted status suffix. Cookie/header lookup and argument scanning have their own separator/case rules; these are compatibility surfaces for modules and variables, not interchangeable generic maps.

Additional preservation tests: every-byte fragmentation of chunk size, extensions and trailers; exact size boundary and overflow values; body plus pipelined next request in a single read; early final response during upload; file-only empty body; buffered filter backpressure; discard timeout; percent-encoded delimiters/dot segments; split header names with underscore policy; HTTP/1.0/0.9 and unknown methods; malformed chunk trailers and optional retained trailers.

## Read batch 4: core phases, locations and configuration

Fully read `ngx_http_core_module.h` (1–604) and `ngx_http_core_module.c` (1–5523).

- The phase engine distinguishes generic, rewrite, find-configuration, post-rewrite, access, post-access and content checkers; handler return codes have different meanings in each checker. Async `AGAIN`/`DONE` suspend processing, while generic `OK` skips to the next phase. Admission or rollout hooks must join the intended phase and honor this contract.
- Main requests alone run access checkers. `satisfy any` suppresses accumulated authentication challenge headers on success; failed access prefers authentication errors over forbidden, and `auth_delay` uses event/timer scheduling including an extra event-loop iteration. Forks must preserve access composition and delayed finalization.
- Location resolution includes exact/inclusive tree matching, nested regex matches, `^~` suppression, variable predicate locations and trailing-slash auto-redirect. Predicates use flushed variables and nonempty/non-`0` truth. Restricting routing to host and path prefixes would remove baseline behavior.
- Location selection updates limit-except configuration, logging, sendfile, body storage and keepalive policy. Declared body size is enforced after selecting the location, except the separate early-body path noted earlier. A rejected body is discarded before 413 finalization.
- Rewrites, internal redirects and named-location redirects decrement the URI-change budget; redirect paths reset module contexts and relevant cache/location state and increment the main reference count before reentering phases. New asynchronous state must survive or explicitly clean up this reset, with no double admission or leaked lease.
- Subrequests share the request pool, incoming headers/body and variables, but receive new contexts/output lists and their own phase state. The code guards reference-counter overflow with reserved headroom, rejects nested in-memory subrequests, decrements subrequest depth, and orders non-background output through postponed requests.
- Configuration compatibility includes directive contexts, inheritance and defaults, build-dependent options and platform checks: root/alias scripts, resolver, MIME types, sendfile/AIO/thread pools, symlink policy, keepalive/lingering, error pages, early hints, PROXY protocol, TCP/MPTCP/QUIC listen restrictions, wildcard/regex server names. Preserving all functions means retaining these branches and build features; an unchanged default HTTP path is insufficient evidence.

Tests required before native changes: phase return-code suspension/resume; access `satisfy all/any` plus challenge headers and auth delay; exact/prefix/nested regex/predicate location precedence; inherited `limit_except`; redirect cycle budget and context resets; subrequest depth/reference overflow and background/in-memory behavior; configured body limit after rewrite; reload validation of platform/build-dependent directives; keepalive request/time limits and file/AIO combinations.

## Read batch 5: HTTP initialization and base output filters

Fully read `ngx_http.c` (1–2245), header filter (1–741), write filter (1–371), postpone filter (1–259), copy filter (1–433), and special responses (1–865).

- HTTP configuration initializes module indices and all configuration levels, runs preconfiguration, parses, merges recursively, builds location trees/header hashes, runs postconfiguration, resolves variables, constructs phase handlers and optimizes listening addresses. Registered phase handlers run in reverse registration order. Output filters are linked during postconfiguration; changing module/build order can alter behavior even without editing handlers.
- Exact/inclusive locations are joined with duplicate detection; regex and predicate ordering is preserved separately. Server names compile into exact/wildcard hashes and ordered regex entries. Address binding distinguishes explicit and implicit binds under a wildcard listener; protocol flags merge with conflict warnings. A runtime route update must retain per-address default server and virtual-name semantics.
- HTTP/1 header emission sets header-sent once, handles HEAD/204/304, skips subrequest/HTTP/0.9 wire headers, computes redirects using TLS/local port and configured host policy, emits framing/connection headers, and supports flushed 103 early hints. Header values come from trusted module output; new management inputs must not be appended as unchecked wire headers.
- The writer retains output chains, rejects invalid zero/negative buffers, honors flush/sync/last markers, sendfile chunk limits, delayed rate timers and low-level buffered state. `response_sent` is set only after the last chain is consumed; it does not bypass finalization's other reference/blocked checks.
- Postponed output enforces parent/subrequest ordering by switching the active request and posting callbacks. In-memory subrequests have their own bounded response buffer and reject declared or actual overflow. Copy filtering adapts file/memory/temp buffer requirements and delegates to the output-chain engine.
- AIO/threaded file operations increment `main->blocked`, arm a diagnostic timer and retain the request until completion; near the blocked-counter limit they fall back to synchronous reads. A timer reporting a slow operation does not pretend the operation completed or release its reference. Completion handles already-finalized subrequests and terminated main requests separately.
- Special responses control keepalive/lingering for specific errors, prevent recursive error-page loops, discard bodies, reset headers/filter contexts, and may perform an internal GET redirect, named-location redirect or external redirect. Header-filter finalization deliberately returns an error to reset pending filter data. New rejection responses must use this machinery rather than writing an independent response into an active filter chain.

Tests required: module/phase/filter ordering with dynamic modules; duplicate and wildcard listener configuration; exact/inclusive location duplicates and escaped redirects; HEAD/204/304/HTTP0.9; 103 followed by final response under backpressure; flush/sync/last buffers and delayed rate limits; file send plus AIO/thread abort/termination; ordered subrequest output and in-memory overflow; error_page recursion/overwrites/method changes; rejection after body/filter work has started.

## Read batch 6: script VM and variables

Fully read script header/implementation (279 + 2002 lines), variable header/implementation (117 + 2895 lines).

- Complex values execute separate length and copy programs and flush noncacheable variables before evaluation. Copy instructions now check the output boundary and abort with 500 if a changing value exceeds allocated space. Capture quoting depends on argument/redirect context and original quoted/plus URI flags; variable substitution cannot be replaced by plain string interpolation.
- Rewrite instructions maintain URI/args, valid-location and valid-unparsed-URI flags, regex captures, break-cycle behavior and internal status. `if` can switch location configuration; file predicates use cached file metadata and symlink policy. Return instructions share ordinary response/discard/filter paths.
- Variable registration honors changeable, weak, prefix, indexed, nohash and nocacheable flags; lookup has a depth guard of 100. Indexed cached values and flushed values deliberately differ. Unknown headers normalize case/dashes, link duplicate fields and combine with the established separators; cookies use semicolon separation.
- Request and wire observations differ: `$host` is normalized server/fallback name while `$http_host` is the actual header; `$request_uri` remains distinct from mutable `$uri`/`$args`; body data is unavailable through `$request_body` after spooling to a temporary file. Content length may remain unknown/no-cacheable while reading. A rollout or policy variable must choose and document the intended representation.
- Existing log variables include status/error status, sent bytes/header accounting, request completion/time, connection counters/time, PROXY protocol/TLVs, TLS-derived scheme, request authority port and per-worker request IDs. Regex named captures populate indexed variables. Preserve evaluation timing, missing-value semantics and shared subrequest variables when adding metadata.

Tests required: noncacheable variable changes across length/copy evaluation; output-boundary guard; captures quoted into redirects/arguments; args mutation invalidating original URI; variable cycles and weak/prefix resolution; duplicated/underscored header variables; body variable before/after disk spill; subrequest regex capture isolation/reallocation; dynamic roots and file predicates under symlink policy.

## Read batch 7: priority and shared Huffman codec

Fully read priority header/implementation (35 + 682 lines), Huffman encoder (242) and decoder (2714), including every literal transition-table row. One oversized combined output was truncated inside the decoder table; the decoder was reread in consecutive 400-line chunks, with no omitted ranges counted.

- The Priority parser implements a strict structured-field dictionary, rejects syntax errors for the whole field, bounds members, inner items, parameters, strings, tokens and binary values, and only applies recognized urgency/incremental values. Duplicate keys replace earlier values, including resetting a previously valid value when the later one has the wrong type/range. Effective priority merges explicit server values over client values.
- Shared HPACK/QPACK Huffman coding uses fixed tables, lowercase-integrated encoding, word-size/endian branches, all-ones terminal padding and a fallback result when compression would not shorten the string. Decoder state is persistent across chunks and rejects invalid/self transitions or an incomplete terminal code. Callers own destination sizing and decoded-header validation; codec correctness alone does not establish header safety.

Preservation tests: structured-field malformed/unknown/duplicate keys and every count/length boundary; server/client override precedence; all-byte encoder/decoder vectors across 32/64-bit and endian builds; every-byte chunk splits, EOS and invalid padding; decoded control characters and output expansion limits in both H2 and H3 callers.

## Read batch 8: complete HTTP/2 and HPACK

Fully read all seven assigned `src/http/v2/` files (8289 lines), including encoder, dynamic/static tables, connection/frame state machine, module configuration and response filter.

- H2 dispatch owns a physical connection and per-request fake connections. It retains shared HPACK state across streams, uses separate connection/stream windows, and can free/recreate the idle working pool without discarding persistent compression state. Header decode pools survive until both parsing and request logging no longer need them.
- Incoming DATA charges full padded frame size against receive windows. Connection-window updates and stream-window updates have different policies; unbuffered/body-filter buffering only reopens the stream window when busy buffers clear. SETTINGS can make a stream's signed send window negative. WINDOW_UPDATE checks zero increments and overflow and wakes waiting/exhausted streams through event handlers.
- HEADERS enforces odd increasing stream IDs, concurrent-stream limits, per-read new-stream limits, refused-stream budget and configured preread behavior before SETTINGS acknowledgement. Refused streams still consume the HPACK block to keep the shared table synchronized. CONTINUATION must be contiguous and use the same stream ID; field lengths, total decoded header budget, HPACK integer octets and Huffman expansion are bounded.
- Header processing rejects uppercase/control/colon names and NUL/CR/LF values, enforces pseudo-header order/uniqueness, synthesizes request line and Host for module compatibility, combines Cookie fields with semicolons, rejects connection-specific headers and non-`trailers` TE, checks raw `:authority`/Host equality, and validates Content-Length against END_STREAM/received body size. This baseline denies CONNECT and TRACE over H2. Protocol limits and errors must remain stream-versus-connection scoped as implemented.
- HPACK dynamic entries use a 4096-byte bounded ring with per-entry 32-byte accounting, eviction, wrapped-name/value copying and index validation. Size updates cannot exceed capacity. A rollout must not replace or reset connection compression state while an existing peer can still refer to it.
- Responses produce HPACK HEADERS/CONTINUATION, DATA and trailing HEADERS with END_STREAM and early-hints flush semantics. Physical output may be partial; shadow buffers propagate consumed offsets to original memory/file buffers. Effective urgency/incremental priority orders data and waiting streams; control/blocked headers retain their required ordering.
- Stream cleanup removes unsent unblocked frames, refunds their reserved connection window, removes waiting nodes and wakes blocked streams. Partially sent/blocked frames keep the stream alive via `queued`; retry-close callbacks defer destruction. RST_STREAM invokes the fake read handler and native request finalization rather than freeing immediately. Connection GOAWAY/exit drains active streams and uses lingering shutdown.
- Flood defenses are distributed: total-vs-payload accounting, 10000 control/data frame allocation budget, concurrent/new/refused streams, idle wake count and 32 closed/idle priority nodes. Preserve the protections as a set. RFC9218 PRIORITY_UPDATE overrides the header; pre-HEADERS priority is bounded and oldest-evicted, an explicitly documented leniency in this source.

Required H2 tests: fragmented preface/frame/HPACK/Huffman blocks; refused or locally canceled stream followed by indexed-header reuse; interleaved/incorrect CONTINUATION; declared/actual body mismatch and padded flow-control accounting; zero/overflow/negative windows and SETTINGS changes; slow consumer reopening windows; reset while body/AIO/output frames are queued or partially written; one stream failure with another healthy stream continuing; flood budgets and idle-priority eviction; GOAWAY during reload/exit; HEAD/204/304, 103 and trailers with sendfile/backpressure; pool lifetime through log handlers.

## Read batch 9: complete HTTP/3 and QPACK

Fully read all 13 assigned `src/http/v3/` files (7362 lines), including every static-table entry, prefix/variable integer encoder and incremental parser, dynamic-table operation, unidirectional stream handler, request/body path, configuration and response filter.

- HTTP/3 has a parent QUIC session and separate stream connections. Session state owns critical-stream slots, the QPACK table and blocked-request queue, keepalive timer and posted insert-count acknowledgement. Cleanup destroys table allocations, cancels the timer and removes the posted event. Request stream counts and connection reuse timers belong to the session, while request pools and finalizers belong to individual streams. QUIC transport packet/stream flow control is outside this manifest; this layer consumes the transport's stream `recv`/`send` interface.
- The module enables HTTP/3 by default when built, leaves HQ interoperability disabled by default, and configures 128 concurrent requests, a 4096-byte QPACK table and three peer unidirectional streams. Unknown stream types, duplicate critical stream types and closure of a critical stream have distinct paths. Locally generated SETTINGS, GOAWAY and QPACK decoder instructions require full writes or terminate the connection. A new drain hook must preserve the protocol's GOAWAY/request-ID boundary and avoid accepting streams after shutdown.
- Control, request-header and body-frame parsers retain explicit state across reads. They decode 1/2/4/8-byte QUIC integers and bounded prefix integers, limit a local parse buffer to the frame's declared length, and distinguish incomplete input from a field that overruns its frame. The control stream requires SETTINGS first, forbids a second SETTINGS frame and rejects inappropriate frame types. Unknown permitted frames are skipped by their declared length. Preserve these scope and consumption rules rather than parsing a whole stream as an unconstrained byte sequence.
- Inbound QPACK supports all five field representation forms, dynamic insertion/name references/duplication, capacity changes, required-insert-count wrapping and blocked sections. An insert allocates and copies the entry before eviction. Dynamic lookup copies names/values into the request-stream pool, so later table eviction cannot invalidate a request header. Blocking registers pool cleanup once, enforces a blocked-stream budget and wakes posted readers when insertions become available; a reader can block again when it still needs a later insert.
- Outbound QPACK in this baseline uses static references and literals with Required Insert Count and Base both zero. There is no outbound dynamic table to preserve. Accordingly, received section acknowledgements and insert-count increments follow decoder-error paths, and stream cancellation is a no-op for outbound compression state. Do not describe this implementation as using bidirectional dynamic compression. Huffman expansion, literal name/value lengths and decoded aggregate header size are bounded separately.
- Request validation enforces pseudo-header order, uniqueness, nonempty required values, normalized URI parsing, lowercase header names, NUL/CR/LF rejection, configured ignored-header policy, header count and aggregate decoded-header budget. Connection-specific fields are forbidden and TE is allowed only as `trailers`. Authority and an explicit Host must match in their original forms. Unlike the H2 path, H3 does not synthesize a Host header when only `:authority` is present; variables/modules must retain the actual per-protocol behavior. The selected virtual server can reject H3/HQ with 421, and CONNECT/TRACE are denied here.
- Body reading uses preread buffers, the common body save filter and free/busy chains. Unbuffered downstream backpressure differs from waiting for the client under a body timer. Each DATA frame's declared size is checked against the remaining Content-Length or configured body limit before its payload is accepted; EOF and declared-versus-received mismatch are validated. Unknown-length bodies use an internal chunked marker without pretending QUIC transmits HTTP/1 chunk framing.
- In this baseline `ngx_http_v3_parse_data` returns completion on the first following HEADERS frame; it does not decode incoming trailer fields there. Outgoing trailers are implemented by the response filter. Preserve and test the actual distinction; this reading does not claim inbound trailer forwarding. Responses with known Content-Length and no trailers can emit one DATA prefix for the complete length; unknown-length/trailer paths generate frame prefixes through a body filter and retain flush/sync/file-buffer semantics. Early hints emit a flushed 103 HEADERS block before the final response.
- Request cleanup marks incomplete responses as errors; stream reset chooses timeout/rejected/internal-error codes by state and sends QPACK cancellation where necessary. Session cleanup, blocked-header cleanup, request cleanup and transport stream reset are distinct operations. Header/read timeouts, configured request count/connection age, GOAWAY and total-versus-payload flood accounting must remain active when adding deployment or admission features.

Required H3 tests: every-byte splits of varints, prefix integers, field sections and encoder instructions; zero/truncated/oversized frame lengths; unknown frame skipping and forbidden frame scope; a blocked QPACK request canceled before an insert; multiple blocked requests waking and reblocking; insertion referencing an entry evicted by that insertion; capacity/required-count wrap and invalid indices; critical-stream duplication/closure; table and posted-event cleanup on connection close; body frame length versus configured/declared size and EOF; slow consumer backpressure; explicit Host versus authority-only variables; GOAWAY boundary with existing streams continuing; known/unknown-length response framing, early hints and outgoing trailers. Transport-level flow-control tests require the separate QUIC implementation review and harness.

## Request path and lifetime map

The paths converge on ordinary HTTP phases and filters, while connection/stream framing remains protocol-specific.

| Stage | HTTP/1 | HTTP/2 | HTTP/3 | Invariant for a native fork |
| --- | --- | --- | --- | --- |
| Accept and dispatch | `ngx_http_init_connection`, read event, optional TLS/SNI/ALPN | `ngx_http_v2_init` after preface/ALPN | `ngx_http_v3_init_stream`, session or request/uni stream setup | Retain per-address/server configuration and native connection ownership. |
| Parse and validate | `ngx_http_process_request_line`, `ngx_http_process_request_headers`, `ngx_http_process_request` | frame/HPACK state handlers, `ngx_http_v2_run_request` | `ngx_http_v3_process_request` and incremental frame/QPACK parsing | Consume exactly the current protocol element; preserve stream-versus-connection error scope. |
| Select and run | `ngx_http_handler`, `ngx_http_core_run_phases` | Same native phases after synthesizing a request | Same native phases after synthesizing a request | Module order, access semantics, redirects and location inheritance remain effective. |
| Read or discard body | `ngx_http_read_client_request_body` and length/chunked/discard filters | Protocol dispatch to `ngx_http_v2_read_request_body` | Protocol dispatch to `ngx_http_v3_read_request_body` | Buffer ownership, timers, temporary files, flow control and declared/actual size agree. |
| Produce response | `ngx_http_send_header`, `ngx_http_output_filter`, configured filter chains | H2 header/body filters and shared physical frame queue | H3 header/body filters and transport stream output | Flush, sync, last, trailers, file buffers and backpressure retain their native meanings. |
| Finalize | `ngx_http_finalize_request`, connection finalize/keepalive/lingering/close | Common request finalization plus `ngx_http_v2_close_stream` and deferred queued-frame cleanup | Common request finalization, request/stream pool cleanup and QUIC close/reset | Logging and cleanup happen once; no pool is freed while references, AIO or queued output still need it. |

`main->count`, `main->blocked`, subrequest depth and output-buffer state answer different questions. A subrequest shares the pool, body and variables but has separate contexts and output ordering. An internal redirect increments references and clears contexts before reentry. Reading/discarding a body, scheduling AIO, retaining a filter chain and queuing a physical H2 frame can each outlive the content handler. Consequently, a new limit lease must be attached to a precisely defined native lifetime and released through an idempotent cleanup; `last_buf`, response completion and socket close cannot be treated as interchangeable release points.

## Native change gates

These are required regression categories, not tests already executed by this reader.

| Priority | Change gate | Minimum evidence |
| --- | --- | --- |
| P0 | Preserve baseline before policy features | Build the unchanged commit with the intended module/build matrix; execute the same configuration and byte-level cases against baseline and fork. Record intentional differences explicitly. |
| P0 | Framing and parser boundaries | Differential HTTP/1 CL/TE/duplicate/Expect/pipelining tests; H2/H3 declared-versus-received DATA tests; incremental parsing split at every byte with exact consumed-byte checks. |
| P0 | Request lifetime and drain | Abort, timeout, body discard, internal redirect, background/subrequest, AIO and partial output cases; assert one cleanup/log, no leaked references and continued healthy peer streams. |
| P0 | Compression and multiplexing | Keep HPACK/QPACK state across refused/reset streams; exercise table eviction and blocking, window exhaustion and wakeup, GOAWAY and critical-stream failure. |
| P0 | Admission without replay or deadlock | Define whether a limit counts main requests, streams, subrequests or work; test every asynchronous exit. Rejecting one request must not corrupt a connection's next request or another stream. |
| P1 | Configuration and module compatibility | Preserve create/init/merge, pre/postconfiguration, variable resolution, listener defaults, dynamic module/filter order, inheritance and SNI/Host selection. |
| P1 | Response equivalence | HEAD/204/304, HTTP/0.9, 103, errors/error_page, redirects, trailers, buffered/unbuffered files, rate delay and sendfile/AIO combinations. |
| P1 | Platform and feature branches | Relevant 32/64-bit, endian, event backend, TLS, HTTP/2/3, threading/AIO and filesystem/symlink build branches. A read of inactive preprocessor branches is not execution evidence. |

The smallest compatible first native increment is an opt-in extension using the existing configuration, phase/filter and cleanup contracts. Retain the native protocol engines and all default behavior. A separate authenticated management plane and immutable configuration generations can coordinate releases, but must not replace native parser, worker, request, filter or compression ownership with laboratory counters. Benchmarks and claims of improvement require reproducible measurements after compatibility gates pass.
