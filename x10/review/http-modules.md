# NGINX HTTP modules source review

Source: commit `148c75678cd4171338c31d4ed4c02411736d5fe9`, declared version 1.31.9. This is a source-reading review, not an execution or compatibility certification. Coverage status and exact line ranges are recorded separately in `http-modules-coverage.json`. Files not fully read are not claimed as fully reviewed.

## Reading notes

Complete bounded source reading: 53 of 53 manifest files, 43,098 lines. The appended checkpoints record the order of reading; the final JSON ledger is authoritative for current coverage.

### Access and authentication (full reads)

- `access` (`allow`, `deny`) registers in ACCESS phase. First matching rule wins for IPv4/IPv6 (including mapped IPv4), with optional UNIX sockets. A location inherits parent arrays only when none of its rule arrays are locally present; preserve `satisfy all/any` interaction supplied by core. Deny returns403; unmatched declines.
- `auth_basic` and `auth_basic_user_file` use compiled complex values, ACCESS phase, realm `off`, 2048-byte bounded password-file scanning, crypt comparison, explicit buffer zeroing and fd cleanup. Missing file gives403 vs other IO failures500. Credentials missing/mismatch yield401+WWW-Authenticate or407+Proxy-Authenticate for proxy auth in this source version.
- `auth_request` and `auth_request_set` implement waited asynchronous subrequests: header-only fake body prevents body ownership/file closure problems; main request resumes with NGX_AGAIN until done. 2xx allows,401/403 denies, unexpected status500.401 copies every challenge header and set variables remain available after internal redirects. Preserve variable set-handler hooks and inheritance.
- Compatibility scenarios: mapped IP/CIDR rule order; mixed local/parent rule sets; auth file edge lines/CRLF/password suffix comments; realm variables/off;401 multiple challenges; auth subrequest body handling/internal redirect variable visibility.

### Request and connection limiting (full reads)

- Both register PREACCESS handlers and use shared slab-memory red-black trees protected by zone mutexes. They deduplicate on `r->main` status; this is request lifecycle accounting rather than a naive process-local socket counter. Keys are compiled complex values; empty keys are skipped. Keys over255 bytes (conn) or65535 (req) are logged/skipped. Zone minimum8 pages; zone names/keys validated and unchanged-key shared state reused across reloads.
- `limit_conn_zone`, `limit_conn`, `limit_conn_log_level`, `limit_conn_status`, `limit_conn_dry_run`; exported `$limit_conn_status` PASSED/REJECTED/REJECTED_DRY_RUN. Counts1..65535. Every accepted zone adds request-pool cleanup; zero count deletes rbtree node/frees slab. Later-zone rejection rolls back previously acquired zone counts via cleanup_all; cleanup allocation failure immediately frees its newly acquired count. Default rejection503, configurable400..599.
- `limit_req_zone`, `limit_req`, `limit_req_log_level`, `limit_req_status`, `limit_req_dry_run`; `$limit_req_status` adds DELAYED/DELAYED_DRY_RUN. Rate r/s or r/m, burst/delay/nodelay use integer thousandths. Leaky excess decays with elapsed ms; clock jumps clamp. Multiple zones reserve node counts before final accounting, unlock them on every failure, and choose the longest required delay. Delay uses event handlers/timers and resumes core phases without blocking workers.
- Request limiter expiration uses queue age/excess and pin counts: normal cleanup deletes old zero-rate entries, allocation failure can force oldest eligible expiration. Dry run exposes policy outcome while allowing traffic. Child local limit arrays replace inherited arrays.
- Preservation tests: cross-worker shared keys, reload same/different zone keys, memory exhaustion, multiple-zone partial admission/cleanup, abort during delayed request, internal redirects/subrequests, burst/nodelay/delay thresholds, clock moves, dry-run variables/status/log level, empty/oversized keys. The Node laboratory global limiter is not equivalent to these semantics.

### Client identity and static routing (full reads)

- `set_real_ip_from`, `real_ip_header`, `real_ip_recursive`: trusted CIDRs/hostnames/UNIX peers; X-Real-IP default, X-Forwarded-For, PROXY protocol or configured header. Runs POST_READ and PREACCESS; relies on trusted-chain helper. Stores original sockaddr/text in request cleanup and restores shared connection fields afterward. Original `$realip_remote_addr`/`$realip_remote_port` survive internal redirects by finding the cleanup even if module context was reset. Preserve trusted proxy boundary before auth/limits.
- Static content handler registers CONTENT without its own directives. Uses core URI/root/alias, open-file cache/read-ahead/directio/symlink policy. Directory redirects preserve args and URI escaping; distinguishes404/403/500; POST regular files405, body discarded; HEAD obeyed. ETag/mtime/content type/length and allow_ranges are set; file-backed output permits sendfile and correct main/subrequest last_buf/sync semantics.
- `try_files` registers PRECONTENT: variable script lengths/value safety, file-vs-directory probes, alias edge cases, named-location/URI+args/status terminal fallback. It rewrites effective URI/extension then declines into content handling; not equivalent to arbitrary SPA fallback rewriting.
- `index` registers CONTENT for slash URIs; list can contain variables and absolute internal redirects; default index.html. Probes first candidate before directory to optimize common case; preserves symlink policy/open-file cache/error classes, aliases/args and config inheritance.
- Compatibility scenarios: persistent connection original address restore; multiheader trusted chains; PROXY source port; filesystem type/symlinks; URI escaping+args301; zero-length files; HEAD and subrequests; aliases with/without trailing slash; try_files named locations/status and variable-buffer bounds; index internal redirect access processing.

### Header conditions, byte ranges and subrequest filters (full reads)

- `not_modified` header filter handles main200 responses only: If-Unmodified-Since/strong If-Match412; conditional If-Modified-Since + weak If-None-Match304 and clears content length/type/ranges/encoding. Core `if_modified_since` off/exact/before behavior matters.
- `headers` directives: `expires`, `add_header`, `add_trailer`, `add_header_inherit`, `add_trailer_inherit`. This source includes explicit inherit off/on/merge; merging appends inherited arrays after local entries. Status allowlist vs `always`, variable values, multiheaders Cache-Control/Link, special ETag/Last-Modified replacement, trailers emitted at final body buffer. Expires supports modified/access, signed durations, epoch/max/off and daily @ time; dynamic invalid value ignored rather than config-time failure.
- `range` separate header/body modules install chained filters; eligibility depends HTTP>=1.0,200, known length, allow_ranges, main/subrequest flags, core max_ranges. If-Range matches exact ETag or date. Parser guards integer overflow and range amplification, suffix/open-ended/multiple ranges;206 single/multipart or416 with Content-Range bytes */size; exceeding max_ranges may decline and send full response. Single-range slices memory/file buffers and preserves chain flags; multipart requires whole body in suitable single buffer, fails on overlapped buffers.
- Filter modules capture previous `ngx_http_top_*_filter` and replace top in postconfiguration; actual cross-module order is governed by build/module registration, not alphabetical filenames. Preserve that source/build order.
- `addition`: add_before_body/add_after_body/addition_types; main200 selected types only; clears length/ranges, weakens ETag, preserves body; before/after subrequests sequenced with last_buf conversion. `mirror`/mirror_request_body runs PRECONTENT, only main request, optional asynchronous body-read then background header-only subrequests preserving method/args. Body default on; subrequest results do not become main response content.
- Compatibility scenarios: condition precedence+weak tags; invalid dates; header inheritance merge/off; duplicate headers/trailer timing; HEAD; suffix/open-ended/overflow/amplifying ranges; filter combinations with compression/subrequests; mirrored request body/file ownership and finalization.

### Chunking, slices and compression (full reads)

- `chunked` has no local directive, uses core chunked_transfer_encoding. Main eligible HTTP/1.1 unknown length/trailers becomes chunked; HEAD/204/304/CONNECT success bypass. HTTP1.0 unknown length disables keepalive. Body chains keep memory/file/flush/sync, prepend size, append CRLF and final0 with every non-disabled trailer. Free/busy tagged chains preserve output backpressure.
- `slice` and `$slice_range`: aligns requested start to configured size, creates clone subrequests sequentially; validates206 Content-Range start/end/complete length and consistent ETag across every slice. Tracks shared context and buffering; rewrites to whole-resource length then cooperates with single-range/subrequest ranges. Overflow/suffix/multipart/If-Range starts handled conservatively. Preserve cache-key/upstream Range integration outside this file.
- `gzip_static off|on|always` CONTENT handler uses file cache/symlink policy to serve .gz, preserves MIME of source name, ETag/mtime/ranges/file-backed output. `on` honors gzip eligibility and Vary; `always` bypasses Accept-Encoding eligibility.
- Dynamic compression directives: gzip, gzip_buffers, gzip_types, gzip_comp_level(1..9), gzip_window, gzip_hash, postpone_gzipping, gzip_no_buffer, gzip_min_length; `$gzip_ratio`. Header eligibility200/403/404, no existing encoding, selected types/min length, not HEAD; gzip_ok/core negotiation/degradation supported. Clears length/ranges, weakens ETag, memory input. Streaming deflate uses bounded buffers/free-busy chains, sync flush/final flush; window/memlevel adjusted for small known bodies; contiguous zlib preallocation and zlib-ng fallback; frees compression allocation at completion, not response end.
- `gunzip` and gunzip_buffers decode gzip only when client cannot accept it; default off,128KiB output budget by pages. Clears encoding/length/ranges, weakens ETag, supports concatenated gzip members via inflateReset. Truncated/invalid streams error, preserve last_in_chain and main last_buf semantics.
- Preserve tests: encoding negotiation/Vary, gzip_static always+gunzip, streaming flush/backpressure/abort, tiny/unknown length, range+compression order, concatenated/truncated gzip, trailer framing, slice changed ETag/missing/wrong206/length/last-buffer and cache separation. Optimizations need benchmark with equivalent settings, not removal of these paths.

### Autoindex (complete read)

`autoindex`, `autoindex_format` (html/json/jsonp/xml), `autoindex_localtime`, and `autoindex_exact_size` configure a CONTENT handler, off by default, for slash-ending GET/HEAD directory URIs. It maps the URI, checks directory errors and sends headers; HEAD closes the directory without enumeration. A temporary pool holds entries, dot names are skipped, symlink metadata has a fallback, per-entry EACCES is ignored, and directories sort before files by name. All paths close the directory; output survives temporary-pool destruction in the request pool.

HTML separately escapes display names and URI components, respects UTF-8 when truncating the 50-character column, and supports local timestamps and exact or rounded sizes. JSON escapes names and reports directory/file/other, GMT modification time, and file size only for files. JSONP permits at most 128 callback characters, limited to letters, digits, underscore and dot; an absent callback returns JSON and an invalid one returns 400. XML escapes names and emits UTC timestamps. Size calculations check overflow. Preserve HEAD, permissions/symlinks, escaping, ordering, JSONP validation, timezone/size modes and large-directory cleanup behavior; changing presentation defaults is a product decision, not source equivalence.

### Charset and DAV (complete reads)

Charset installs header/body filters and supports `charset`, `source_charset` (literal or indexed variable), `override_charset`, `charset_types`, and `charset_map`. Defaults are charset/source off and override off. Main-request destination charset is shared with subrequests; 301/302 omit it for legacy client behavior. Content with another Content-Encoding is not recoded. Single-byte maps can rewrite temporary buffers in place; UTF-8 conversions clear main Content-Length, demand in-memory data, retain incomplete sequences across chain buffers, reuse tagged free/busy buffers and consume shadow buffers only after downstream consumption. Unrepresentable Unicode becomes a numeric HTML entity; malformed sequences become `?`. Mapping configuration is bidirectional, rejects duplicate/self maps, requires UTF-8 in the second column, limits mapped Unicode to UCS-2, and validates statically required maps during postconfiguration. Missing dynamically selected maps log and pass the response onward. Preserve streaming split sequences, output flags, subrequests, variable charsets and content negotiation rather than substituting a generic whole-body transcoder.

DAV is a CONTENT handler with `dav_methods` (off/PUT/DELETE/MKCOL/COPY/MOVE), `create_full_put_path`, `min_delete_depth`, and `dav_access` (default0600). PUT insists on a clean persistent temporary body file, rejects collection URIs and ranged PUT, atomically renames with configured permissions/path creation, applies a valid Date, and returns201/new or204/replaced with escaped Location. DELETE rejects bodies, checks configured minimum URI depth, treats symlinks through link metadata, requires infinity Depth for collections and0/infinity for files, recursively walks then deletes. MKCOL requires a slash-ending URI and no body. COPY/MOVE validate Destination scheme/host or absolute path, unsafe URI syntax, collection slash consistency, alias location prefix, Depth, Overwrite, normalized paths, and self/ancestor/descendant targets before filesystem operations. MOVE prefers rename, otherwise tree copy/delete; copies preserve access/mtime. Disk-full maps507, permission403, existing405, other errors500. Tree callbacks explicitly contain TODO207 and can log individual failures while continuing; do not promise full WebDAV/transactional multi-status behavior. Compatibility coverage must include cross-filesystem moves, overwrite failures, path/alias boundaries, symlinks, Depth, permissions, disk exhaustion and temporary-file cleanup.

### Geo address maps (complete read)

`geo` defines a lazy variable from the connection address or an explicitly named source variable. Block syntax supports CIDR/value, `default`, `delete`, `ranges`, `proxy`, `proxy_recursive`, `include` (including glob delegation), and `volatile`. CIDR lookup uses IPv4/IPv6 radix trees with mapped IPv6 converted to IPv4; invalid or UNIX addresses map through255.255.255.255. Range mode is IPv4-only, uses upper16-bit buckets with ordered lower ranges, supports contained-range splitting and exact deletion, warns/replaces exact duplicates and rejects unsupported overlap. Values are deduplicated through a configuration rbtree; temporary parse pools are reset and destroyed separately from durable configuration. Trusted forwarding uses the core forwarded-address walker without rewriting the connection.

Large single range includes can generate a binary cache; loading verifies timestamp, magic/version/pointer size/endianness, minimum size and CRC before relocating offsets. Binary and ordinary entries cannot be mixed. The loader explicitly relies on checksum integrity for its subsequent unbounded contiguous walk: this is a local trusted configuration artifact, not a safe untrusted upload format. Preserve address fallback, longest-prefix semantics, range overlap policy, include reload behavior, binary-cache incompatibility fallback and lazy/volatile variable evaluation; a remote GeoIP product is a separate addition.

### GeoIP / MaxMind databases (complete read)

`geoip_country`, `geoip_org`, `geoip_city` accept a database and optional utf8; `geoip_proxy` and `geoip_proxy_recursive` select trusted forwarded addresses. This source has both legacy GeoIP and MaxMindDB compile branches. MMDB is attempted first, mmap-opened, and invalid metadata can fall back to legacy; legacy databases use memory cache and validate supported country/org/city editions including optionalIPv6. Configuration pool cleanup closes every opened database. Variables expose country alpha2/alpha3/name, organization, continent, region/name, city, postal, latitude/longitude(four decimals), metro/DMA and area code. MMDB uses fixed typed paths, English names, an explicit alpha2-to-alpha3 table and ordered organization fallback (AS organization,ISP,organization,domain); area code is absent in MMDB. Legacy allocated records/strings are copied then freed; missing fields return not_found. IPv4-mapped IPv6 is handled deliberately; pureIPv6 against anIPv4 MMDB declines. Preserve compile-dependency combinations, database semantics, encoding, absent fields and cleanup across reload; a data-provider migration must be explicitly tested rather than called equivalent.

### Image filter (complete read)

The GD-dependent header/body filter supports `image_filter` off/test/size/resize/crop/rotate, `image_filter_jpeg_quality`, `image_filter_webp_quality`, `image_filter_sharpen` (numeric or complex values), transparency/interlace flags and a bounded input buffer(default1MiB). JPEG/GIF/PNG/WebP signatures determine type; WebP transforms require compiledGDWebP support. It delays headers until testing/processing, rejects multipart/x-mixed-replace and oversized/invalid input (normally415), disables ranges and buffers the full image for size/transform; test mode passes a recognized image directly. The first chain buffer must contain at least16bytes for signature testing, an observable streaming boundary to test.

Size mode replaces output with JSON dimensions/type or `{}` and cleans response headers. Resize preserves aspect ratio without enlarging an already fitting image, crop resamples then center-crops, rotation supports90/180/270 and coordinates interact with resize/crop. JPEG application metadata exceeding5% forces re-encoding. Palette transparency, truecolor alpha, sharpening, interlace, JPEG75/WebP80 defaults and weak ETag after re-encoding are compatibility details. GD images are destroyed on transform/error paths; GD output is freed through request-pool cleanup, including allocation failure. Input buffer limits do not by themselves cap decoded image memory or CPU. Preserve valid fixture pixels/dimensions, malformed/truncated formats, tiny first buffers, unknown length, HEAD/error-page recursion and library/version build combinations; adding newer formats or process isolation is a separately validated enhancement.

### Access logging (complete read)

LOG-phase `access_log` supports multiple targets, off, static/variable paths, syslog, named formats, conditional `if=`, buffering, flush timers and optional gzip(level1..9). `log_format` compiles literals plus indexed variables, with default hex escaping, JSON escaping or explicit none; missing values become `-` only under default escaping. Optimized variables include pipe,time_local,time_iso8601,msec,request_time,status,bytes_sent,body_bytes_sent,request_length. Non-cacheable variables are flushed before each format evaluation; each copy operation checks its planned output boundary, covering variables whose values change between length and emission.

Buffers flush when full, by configured timer or file flush hook; oversized lines bypass the buffer. Conflicting buffer settings for the same file reject configuration, variables in buffered filenames and buffered syslog are prohibited, and flush requires a buffer. Gzip produces independent blocks through a temporary pool and defaults64KiB/level1. Dynamic paths test root existence, honor symlink policy and optional `open_log_file_cache` (max required; inactive10s,valid60s,min_uses1 defaults); several internal write/setup failures deliberately report simulated success after logging an error. Disk-full suppresses writes for one second; alert repetition is limited to roughly once a minute; partial writes are reported rather than retried. Thus access logs are not a durable audit transaction guarantee. Preserve escaping, absent fields, inherited log replacement/off, buffering/rotation/shutdown, dynamic-path permissions, gzip compatibility, syslog framing and disk-failure behavior. Structured export/central monitoring may be added without silently changing existing formats.

### Substitution and XSLT filters (complete reads)

`sub_filter` registers at most255 nonempty case-insensitive literal patterns, with complex search/replacement values, MIME selection (`sub_filter_types`, defaultHTML), per-pattern once behavior(defaulton), and optional Last-Modified retention(defaultoff). Static search tables are built during configuration; dynamic searches are evaluated per request and empty runtime patterns skipped. A shift/index table searches streams with up to max-pattern-length-minus-one lookbehind. Replacement values are evaluated lazily and cached per pattern. Free/busy/shadow chains preserve zero-copy spans, file offsets, flush/final flags, and downstream backpressure. Main Content-Length is removed; validators are cleared unless last_modified is enabled, which weakens ETag. Local search rules replace inherited rules. Preserve boundary-spanning, overlapping/duplicate patterns, case folding, empty replacements, once-per-pattern semantics, subrequests and flush behavior; it is not a regex filter or HTML parser.

XSLT depends on libxml2/libxslt, with optionalEXSLT. Directives are `xml_entities`, `xml_external_entities`(defaultoff), `xslt_stylesheet`(ordered chain,location), `xslt_param`(XPath expression), `xslt_string_param`(quoted literal), `xslt_types`(defaulttext/xml), and `xslt_last_modified`(defaultoff). Configuration deduplicates parsed DTD/stylesheets and frees them through pool cleanup. A push parser consumes chunks but retains the XML document for whole-document transformation; headers wait, ranges are disabled, each sheet replaces/frees its predecessor document, output Content-Length/MIME/charset follow the final sheet and validators clear/weaken as configured. Empty/invalid transformed output returns500.

Parser options include NOENT,DTDLOAD,NONET,NOWARNING; the external-subset callback substitutes the configuredDTD. With external entities off, system identifiers declared in the document are removed or replaced with empty entities, while public identifiers may still resolve via system XML catalogs. This is a specific compatibility policy, not a blanket no-filesystem guarantee for arbitrary stylesheets/catalogs. Sheet parameters accept colon-delimited URI-unescaped name=value pairs; quoted params deliberately differ from expressions. Request output and parser/docs/transform contexts have explicit free paths; parser-global cleanup runs at process/master exit. Preserve malformed XML, entity/catalog policy, importedsheet encoding/MIME, sequential sheets, dynamicparams, subrequests, libraryversions and header-only/error paths; sandboxing untrusted stylesheets would be a separate feature.

### SSI and extension interface (complete .c/.h reads)

`ssi`, `ssi_silent_errors`, `ssi_ignore_recycled_buffers`, `ssi_min_file_chunk`, `ssi_value_length`, `ssi_types`, and `ssi_last_modified` configure a streaming header/body filter. Defaults: off, errors visible, recycled buffers honored, file chunk1024,value255,HTMLtypes,Last-Modifiedoff. Main responses lose Content-Length/ranges, preserve the body for subrequests and clear validators or weaken ETag. A request/main shared context carries variables, regex captures and named blocks; when a subrequest precedes main filtering, its shared context is copied forward deliberately.

The parser is a resumable state machine for comment commands, quotes/backslashes and split buffers; command/parameter names max32, parameter count16, values bounded by configured length. Unknown/missing/duplicate parameters or malformed commands log and emit the configured error string unless silent. Body spans use free/busy/shadow chains, optional file-buffer passthrough, correct ownership after downstream consumption, and suspend/resume around waited subrequests. The public header describes the command registry extension interface used by the Perl module.

SSI commands are `include`(virtual/file,wait,set,stub), `echo`(var,default,encoding), `config`(errmsg,timefmt), `set`, `if/elif/else/endif`, `block/endblock`. Includes evaluate variables and relative URI prefix, parse unsafe URI and split args before making a core subrequest; virtual includes can be asynchronous, file includes wait, set captures in-memory output and waits, set/stub are exclusive, and only one wait can be active. Stub blocks provide fallback only when a subrequest produced no output; repeated blocks copy buffer descriptors. SSI variables override ordinary core variables, are case-normalized, and regex captures/named captures requirePCRE. Expressions allow nonempty tests, equality/inequality and slash-delimited regex; nested if is explicitly rejected. ## Registration points and filter execution

These are the registration points directly read in the assigned modules. Core dispatch, HTTP/2 and HTTP/3 protocol internals are separate reviews; registered handlers may decline, suspend or finish a request, so this table is not a promise that every row runs on every request.

| Stage | Assigned modules | Ordering/ownership consequence |
| --- | --- | --- |
| POST_READ and PREACCESS | realip | Establishes a trusted address before access decisions and restores the connection address at request cleanup. |
| SERVER_REWRITE and REWRITE | rewrite | Separate server and location script execution; redirects can re-enter core location processing. |
| PREACCESS | realip, limit_conn, limit_req, degradation | Address trust, shared admission state and delayed request resumption must stay compatible with core phase dispatch. |
| ACCESS | access, auth_basic, auth_request | Core satisfy all/any and asynchronous auth-request completion govern combined results. |
| PRECONTENT | mirror, try_files | Mirror body-read may suspend; try_files selects effective URI/fallback before content. |
| CONTENT phase registry | static, gzip_static, dav, autoindex, index, random_index | Handlers have different eligibility and decline behavior; source/build registration order must be retained. |
| Explicit location content handler | empty_gif, flv, mp4, stub_status, perl, tunnel | Their directive installs the core location handler; not an additional unconditional phase pass. |
| LOG | log | Completion logging with lazy variables, buffering, and failure policy. |
| Lazy variables/configuration and TLS callbacks | browser, geo, geoip, map, split_clients, referer, secure_link, json, ssl | Evaluated when used or at handshake/configuration, not a standalone content phase. |

Targeted supporting reads additionally checked `ngx_http_init_phase_handlers` (`src/http/ngx_http.c`, lines 440–565), `ngx_http_core_content_phase` (`src/http/ngx_http_core_module.c`, lines 1275–1385), the phase enum (`src/http/ngx_http_core_module.h`, lines 109–141), and log dispatch (`src/http/ngx_http_request.c`, lines 4080–4105). Core phases proceed POST_READ → SERVER_REWRITE → FIND_CONFIG → REWRITE → POST_REWRITE → PREACCESS → ACCESS → POST_ACCESS → PRECONTENT → CONTENT; synthetic post stages are only installed when needed. Handlers within those phase arrays are copied into the engine in **reverse registration order**. LOG is a separate completion loop in **forward registration order**. The explicit `r->content_handler` takes priority over the CONTENT registry; otherwise a content handler must return NGX_DECLINED to try the next one.

For the inspected generated native profile, actual applicable module order within the registered arrays is PREACCESS realip → limit_req → limit_conn; ACCESS access → auth_basic → auth_request; PRECONTENT try_files → mirror; CONTENT index → autoindex → dav → gzip_static → static. A handler may skip or end the phase, so later handlers are not guaranteed to run. In particular, try_files terminal redirects/status fallbacks can prevent mirror from being reached at that location. Degradation and random_index are absent from this generated profile; enabling them changes their phase arrays. This distinction is essential for importing existing configuration and for a console promising mirror/limit policies.

For filters, installation captures the previous top pointer and replaces it. Thus execution follows **reverse installation order for that particular header/body chain**, excluding modules that do not install that chain. Supportive evidence was read separately: `auto/modules` lines 150–205 and 385–445 (partial supporting read), and the complete generated `nginx-native-build/objs-x10/ngx_modules.c` from the current native build at the pinned source commit. The six core/protocol initializer snippets were inspected only for chain registration; they are not included in this 53-file full-read claim.
